# 调研：VitePress 之外的交互式教学内容呈现方案

> 调研日期：2026-08-06
> 调研目标：为 WorkBuddyGuide（27 章 Markdown 蓝皮书）寻找比 VitePress 更适合的呈现方案。
> 需求画像（用户原话拆解）：**左右栏 / 上下分栏 / 抽屉式布局；一个页面聚合多种内容块；可以随意调用；能进入"教学过程"的交互形态**。
> 一句话结论：**没有现成的开箱方案完美匹配这个需求——你要的不是"文档站"也不是"幻灯片"，而是一个"教学驾驶舱"（Teaching Workbench）。最优解是自研轻量 Workbench，但可用现成组件把成本压到很低；Quarto Dashboards 是最接近的开箱替代品。**

---

## 一、需求翻译：你要的到底是什么

把需求拆成四个能力维度，后面所有方案都按这四维打分：

| 维度 | 含义 | VitePress 为什么不够 |
|------|------|---------------------|
| **D1 多面板布局** | 左右栏、上下分栏、抽屉，一屏放多个内容块 | 单栏长文模型，侧边栏只是导航 |
| **D2 按需调用** | 提示词库、案例图、视频等内容块可随意唤出/收起 | 内容固定在页面流里，不能"召唤" |
| **D3 教学过程** | 有"步骤推进"概念：第 1 步→第 2 步→验收，像上课不像读书 | 无步骤状态机，读者自己找位置 |
| **D4 深度交互** | 内容块本身可操作（复制、填空、勾选、分支选择） | 仅有基础代码复制 |

关键认知：D1+D2 是 **IDE/工作台** 的交互语言（VS Code、Figma 都是左右栏+抽屉）；D3 是**课程软件**的交互语言。你要的是两者的合体——这在产品形态上叫 **Workbench / Cockpit**，不是文档站的升级版。

---

## 二、候选方案全景（按匹配度排序）

### 方案 1：自研轻量 Workbench（Next.js/React + MDX + 面板组件库）⭐ 推荐

**思路**：不找"更好的文档框架"，而是用成熟的 React 组件积木，自己拼一个教学驾驶舱。听起来重，实际上核心布局库已经把最难的部分做完了。

**已验证的关键组件**：

| 需求 | 现成组件 | 验证来源 |
|------|---------|---------|
| 左右/上下可拖拽分栏 | `react-resizable-panels`：PanelGroup/Panel/PanelResizeHandle 三件套，支持嵌套（IDE 式三栏 40 行代码）、折叠、`autoSaveId` 布局记忆到 localStorage、键盘无障碍，约 12KB gzip | [npm](https://www.npmjs.com/package/react-resizable-panels)、[2026 指南](https://viprasol.com/blog/react-resizable-panels/) |
| 抽屉（drawer） | shadcn/ui 的 `Sheet` 组件（上下左右四向抽屉）+ `Resizable`（官方就是对 react-resizable-panels 的封装） | [shadcn 生态说明](https://viprasol.com/blog/react-resizable-panels/) |
| Markdown 内容驱动 | MDX：原有 27 章 Markdown 几乎原样迁移，交互组件以 JSX 形式嵌入 | [MDX 工具对比](https://buildwithfern.com/post/api-documentation-platforms-mdx-component-support) |
| 文档骨架（可选） | Fumadocs：headless 文档框架，Content/Core/UI 三层分离，自带 Tabs（支持 localStorage 持久化）、Accordion、Steps 组件，可当 Workbench 的内容层 | [fumadocs.dev](https://www.fumadocs.dev/)、[组件文档](https://www.fumadocs.dev/docs/ui/components/tabs) |

**目标布局草图**（与需求逐条对应）：

```
┌──────────────────────────────────────────────────────┐
│ 顶栏：章节切换 + 学习进度                        │
├───────────┬──────────────────────────┬───────────────┤
│ 左栏       │ 中央教学舞台              │ 右栏（抽屉）   │
│ 章节树     │ 当前步骤的内容             │ 提示词库       │
│ (可折叠)   │ 图文/视频/演示             │ 案例截图       │
│           │                          │ 相关概念卡     │
│           │                          │ ←点击唤出/收起 │
├───────────┴──────────────────────────┴───────────────┤
│ 底部步骤条：① 痛点 → ② 框架 → ③ 跟练 → ④ 验收  (D3)   │
└──────────────────────────────────────────────────────┘
     所有分栏可拖拽调宽、可折叠、布局记忆 (D1+D2)
```

- **优势**：四个维度全部满分；技术栈与工作区现有能力（webapp-building skill、Tailwind、shadcn/ui）完全重合；内容仍是 Markdown/MDX，"单一母本"原则不破
- **成本**：骨架 2-3 天（布局库拼合），之后每章是"填内容"而非"写代码"
- **风险**：需要维护一个真正的 Web 应用（构建、部署），比 VitePress 运维重

### 方案 2：Quarto Dashboards ⭐ 最接近的开箱替代

**是什么**：Quarto 的仪表盘格式，用 Markdown 标题声明布局——Page（多页）、Row/Column（上下左右分栏）、Tabset（页签）、Card（内容卡片）、**Sidebar/Toolbar（侧栏与工具栏，天然支持"输入控件放侧栏"）**。可纯静态部署，也可用 Observable JS 做响应式交互（滑杆/复选框改变，内容联动更新）。
来源：[Quarto Dashboards 官方文档](https://quarto.org/docs/dashboards/)、[布局与交互](https://quarto.org/docs/interactive/layout.html)

- **匹配度**：D1 多面板 ✅（row/column/tabset/sidebar 原生）；D4 交互 ✅（Observable JS 响应式）；D2 按需调用 ⚠️（有 sidebar/tabset 但无抽屉、不可拖拽）；D3 教学过程 ⚠️（无步骤推进概念）
- **优势**：Markdown 直接写，27 章迁移成本最低；静态部署零后端
- **短板**：布局是"声明式网格"不是"自由工作台"；Observable JS 生态偏数据可视化
- **适合**：作为**快速验证版**——先用它把"四个一"压缩后的章节做成多面板页，验证交互形态是否提升学习效果，再决定要不要上方案 1

### 方案 3：marimo（响应式笔记本即应用）

**是什么**：Python 响应式笔记本，隐藏代码后 `marimo run` 直接变成 Web 应用。布局能力实测很强：`mo.sidebar`、`mo.hstack/vstack`（左右/上下栏）、`mo.accordion`、`mo.ui.tabs`、`mo.nav_menu`，另有**拖拽式 Grid 布局编辑器**和 reveal.js 驱动的 **Slides 布局**（左缩略图栏 + 右配置栏 + 底部演讲备注）。UI 元素与 Python 响应式联动。
来源：[marimo 关键概念](https://docs.marimo.io/getting_started/key_concepts/)、[Run as app](https://docs.marimo.io/guides/apps/)

- **匹配度**：D1 ✅ / D4 ✅✅（交互性全场最强）/ D2 ⚠️ / D3 ⚠️
- **短板**：内容要改写成 Python cell（`mo.md(...)`），27 章纯文字内容迁移性价比低；多页应用要 `mo.routes` 或多 notebook gallery
- **适合**：只做**需要"动手算/动手调"的章节**（如第 18 章投资分析、数据分析类案例），作为嵌入式交互实验场，不适合整站

### 方案 4：TutorialKit（StackBlitz 出品，交互式编程教程框架）

**是什么**：专为"教学过程"设计的框架——**左边课程说明（Markdown 撰写）+ 右边实时代码编辑器/终端/预览窗格**，浏览器内跑真实开发环境（WebContainers）。教程按 Part > Chapter > Lesson 组织，支持"显示答案"、起始代码/答案代码分离。Astro 构建，静态部署（需跨域隔离 headers）。
来源：[StackBlitz 官方发布文](https://blog.stackblitz.com/posts/announcing-tutorialkit/)

- **匹配度**：D1 ✅（它的 UI 就是你描述的左右栏）/ D3 ✅✅（步骤推进是它的核心模型）/ D2 ⚠️ / D4 ✅（但交互对象是"代码"，不是一般内容块）
- **短板**：为**编程教学**而生。蓝皮书大部分章节是"用 WorkBuddy 操作"而非"写代码"，套不进去
- **适合**：仅限第 9 章（接入外部 API）这类真正涉及代码的章节，或未来出"Skill 开发教程"时启用

### 方案 5：Slidev（开发者幻灯片）

**是什么**：Markdown → 幻灯片，Vue 组件可内嵌、`v-click` 步进动画、代码行级高亮动画、Presenter 模式（演讲备注/录制）、two-cols 布局、导出 PDF/PPTX/SPA。
来源：[Slidev 官网](https://sli.dev/)、[定制文档](https://sli.dev/custom/)

- **匹配度**：D3 ✅（逐页推进 + v-click 就是教学节奏）/ 其余弱（线性翻页模型，无工作台感）
- **定位**：不是 VitePress 的替代，而是**内容出口之一**——每章的"四个一"提取结果生成 deck，正好落在 Slidev 上（详见 `02-内容路线图` 与 `05-压缩建议`）。可作为方案 1 中央舞台的"演示模式"

### 方案 6：H5P（开源交互课件标准）

**是什么**：教育领域事实标准的交互内容格式：Branching Scenario（分支剧情/自适应学习路径）、Course Presentation（带测验的幻灯片）、Interactive Video（视频内嵌题目）、Accordion、Dialog Cards、Image Hotspots 等数十种类型。可嵌入 Moodle/Canvas/Drupal 或独立托管。
来源：[H5P Branching Scenario](https://h5p.org/branching-scenario)、[UCSF 内容类型清单](https://libraryhelp.ucsf.edu/hc/en-us/articles/1500001720601-H5P-Overview)

- **匹配度**：D3 ✅（分支场景是"教学过程"的成熟范式）/ D4 ✅ / D1 ❌ / D2 ❌
- **短板**：UI 风格偏传统课件；创作需要在 H5P 编辑器里逐个搭，无法从 Markdown 批量生成
- **定位**：不推荐作为主方案；但"**分支场景**"这个交互范式值得抄——方案 1 的中央舞台可以实现"选 A 路径/选 B 路径"的分支教学

### 方案 7：Idyll / 交互叙事（scrollytelling）

**是什么**：学术论文级"可探索解释"（Explorable Explanations）工具，Markdown 扩展语法 + 响应式变量 + Scroller/Stepper 组件（滚动驱动图形变化）。
来源：[Idyll 官网](https://www.idyll-lang.org/)、[UIST 论文](https://idl.cs.washington.edu/files/2018-Idyll-UIST.pdf)

- **定位**：适合做单篇"惊艳"的交互科普长文（比如神经科学赛道的解毒文章），但项目活跃度未在本轮核实 ⚠️，且是单页叙事模型，不做整站。**作为特别篇内容形态备选**

### 方案 8：Fumadocs / Nextra / Starlight（文档框架升级版）

都已确认支持 MDX 内嵌交互组件（Tabs/Accordion/Steps/Callout），比 VitePress 交互性好，但**仍是"一页一章"的文档模型**——D1-D3 无质变。
来源：[Fumadocs vs Nextra vs Starlight 对比](https://www.pkgpulse.com/guides/fumadocs-vs-nextra-v4-vs-starlight-documentation-sites-2026)

- **定位**：如果最终判断"工作台"投入过大，退路是把 VitePress 迁到 Fumadocs，用 Tabs/Accordion/Steps 做"轻交互版"。**保底线，不是目标线**

### 彩蛋选项：Kimi Work Blueprint Widget（零部署验证场）

你当前的 Kimi Work 环境原生支持把**单页 HTML 应用**做成持久 Widget（任意布局：左右栏、抽屉、步骤条全都可以写），直接投放在对话/看板里，无需部署。
- **定位**：方案 1 的**零成本原型场**——先把"教学驾驶舱"做成一个 Widget 验证交互设计，跑通了再正式开发 Next.js 版。（此项来自本运行时能力，非外部来源）

| 方案 | D1 多面板 | D2 按需调用 | D3 教学过程 | D4 交互 | 内容迁移成本 | 运维成本 | 结论 |
|------|----------|------------|------------|--------|------------|---------|------|
| **自研 Workbench** | ✅✅ 拖拽/折叠/记忆 | ✅✅ 抽屉召唤 | ✅ 底部步骤条 | ✅✅ | 低（MDX） | 中 | **主推荐** |
| **Quarto Dashboards** | ✅ 声明式分栏 | ⚠️ tabset/sidebar | ⚠️ | ✅ OJS 联动 | **最低** | 低（静态） | **快速验证版** |
| marimo | ✅ | ⚠️ | ⚠️ | ✅✅ | 高（改 Python） | 低 | 局部实验章节用 |
| TutorialKit | ✅ | ⚠️ | ✅✅ | ✅（限代码） | 中 | 低 | 仅编程章节用 |
| Slidev | ❌ | ❌ | ✅ | ✅ | 低 | 低 | 内容出口（deck） |
| H5P | ❌ | ❌ | ✅✅ 分支 | ✅ | 高（手工搭） | 中 | 只借"分支"范式 |

## 四、落地建议：三步走

### Step 1：Widget 原型（1-2 天，零风险）
用 Blueprint Widget 做一个"教学驾驶舱"原型：左栏章节树 + 中央步骤舞台 + 右侧抽屉提示词库 + 底部步骤条，内容填第 11 章的"四个一"。**先验证交互形态，不急着写后端。**

### Step 2：Quarto Dashboard 批量验证（1 周）
如果原型手感对，用 Quarto Dashboards 把 5-8 个核心章节批量转成多面板静态页（Markdown 迁移成本最低），**挂出去看真实用户数据**——多面板形态是否真的比长文提升完读率。

### Step 3：正式 Workbench 开发（数据说了算）
数据验证后，用 Next.js + MDX + react-resizable-panels + shadcn/ui 开发正式版。Slidev 继续做 deck 出口，TutorialKit 留给编程章节，H5P 的分支范式融入步骤条设计。

### 与原有三形态计划的关系
本调研不改变 `04-转化方案` 的三形态矩阵，只是**升级了"网站"这一形态的定义**：从"VitePress 文档站增强"改为"教学驾驶舱"。视频和 Slides 产线不受影响。

## 五、未核实事项（诚实标注）

- Idyll 项目当前维护活跃度未核实（官网可访问，但 GitHub 最近提交未查证）
- react-resizable-panels 引用的是 2026 年第三方指南，v3 API 细节（`PanelOnCollapse` 等）以 [npm 官方页](https://www.npmjs.com/package/react-resizable-panels)为准
- H5P 独立托管（脱离 Moodle）的具体部署复杂度未实测
- Quarto Dashboards 中文内容渲染与移动端表现未实测
