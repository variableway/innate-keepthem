# WorkBuddyGuide 内容转化方案：视频 / Slides / 网站

> 仓库：`WorkBuddyGuide/`（https://github.com/AlephAITech/WorkBuddyGuide，已克隆至工作区）
> 性质：VitePress 文档站《WorkBuddy 实战蓝皮书：从安装使用到 AI 工作系统》
> 本文档给出将仓库内容转化为**视频、Slides、网站**三种形态的完整方案。

## 二、形态一：网站（成本最低，先做）

### 现状
网站其实已经存在：`npm run dev`（VitePress）即可本地预览，`npm run build` 可静态部署。SEO、OG 图、域名验证文件都已就绪。

### 方案分级

| 级别 | 动作 | 周期 | 适合阶段 |
|------|------|------|---------|
| L1 直接部署 | `vitepress build` → 部署到 Vercel/Netlify/服务器（仓库已有 `DEPLOYMENT.md`） | 半天 | 立刻可做 |
| L2 体验增强 | 加全文搜索优化、章节进度标记、"案例 → 相关章节"双向跳转、移动端性能优化（`plans/` 已有设计方案） | 1-2 周 | 有流量后 |
| L3 营销着陆页 | 在文档站之外做一个转化导向的 Landing Page：首屏痛点 → Before/After 案例 → 学习路径 → 引流到文档站/视频 | 1 周 | 配合视频发布 |

### 建议
**先 L1 部署上线**（成本几乎为零，内容已经写完），把网站作为所有其他形态的"内容母港"——视频描述区、Slides 结尾二维码都指向它。L3 着陆页等视频发布后做，承接流量。

## 三、形态二：Slides（性价比最高，第二步做）

### 为什么先做 Slides
内容是 Markdown + 表格 + 提示词代码块，用 markdown-native 的幻灯片工具（**Slidev** 或 **Marp**）可以近乎自动化地把章节转成 deck，人工只需要做视觉质检。每条产线一次搭建，27 章批量产出。

### 产品线设计（不要只做一种 deck）

| 产品线 | 内容来源 | 张数 | 用途 |
|--------|---------|------|------|
| **总览 deck × 1** | `reading-guide.md` + 各篇 index | 15-20 页 | 宣讲/引流：《一张图看懂 WorkBuddy 学习路径》 |
| **篇级教程 deck × 4** | 四篇各一份 | 每份 25-40 页 | 系统教学/内训 |
| **章节 workshop deck × 11** | 第二篇案例篇 11 章 | 每份 10-15 页 | 15 分钟工作坊：痛点(2页) → 五问工作流(2页) → Skill 选择(2页) → 跟练提示词(3页) → 验收清单(1页) |
| **速查卡 deck × 1** | 附录 A + 附录 B | 每场景 1 页 | 可打印的提示词卡片 |

### 单页转换规则（章节 → 页面的机械映射）

```
章标题 + 痛点段落        → 封面页 + "你为什么需要这个"页
五问工作流表格          → 一页五宫格
Skill 推荐表            → 一页表格（精简到 5-7 行，其余放备注）
推荐流程步骤表          → 一页横向流程图（WorkBuddy 做 vs 人确认 双泳道）
提示词示例代码块        → "跟练页"：整页就是提示词 + "照抄即可用"
章末要点               → 验收清单页（checkbox 样式）
```

### 工具选择

| 工具 | 优势 | 适合 |
|------|------|------|
| **Slidev** | Markdown 原生、可写 Vue 组件、导出 PDF/PPTX、代码高亮好 | 批量产线首选，与 VitePress 技术栈同源 |
| Marp | 更轻量，纯 Markdown | 速查卡这类简单 deck |
| PPTD/kimi-slides | 精品单 deck，设计质量最高 | 总览 deck 和对外宣讲 deck |

### 品牌一致性
沿用仓库已有的像素绿设计体系（`docs/plans/2026-07-10-workbuddy-pixel-green-ui-design.md` + `@fontsource/silkscreen` 字体），Slides 与网站视觉统一。

## 四、形态三：视频（成本最高但传播最强，第三步做）

### 三层视频矩阵

| 层级 | 形态 | 时长 | 内容来源 | 产出节奏 |
|------|------|------|---------|---------|
| **L1 短视频** | 场景痛点 + Before/After | 60-90 秒 | 附录 B 场景速查表 + 案例截图 | 每周 2-3 条，可量产 |
| **L2 章节教程** | 录屏实操 + 解说 | 8-12 分钟 | 第一篇 10 章（安装→第一个任务→Skill→自动化） | 每周 1 条 |
| **L3 案例纪录片** | 完整案例复盘 | 5-8 分钟 | `cases/submissions/` 7 个案例（截图链完整） | 每月 2 条 |

### L1 短视频脚本模板（60-90 秒，直接可用）

```
0-3s   钩子：痛点场景（"月底做年报，30 个 Excel 要合并"）
3-15s  Before：展示手动操作的痛苦（可用案例素材图）
15-50s 方法：WorkBuddy 怎么做（屏幕录制，3-4 个关键步骤）
       全程字幕 = 章节里的"步骤表"精简版
50-70s After：结果展示（案例里的 result 截图）
70-90s 引导："提示词放在评论区 / 完整教程看简介链接"→ 导流到网站
```

### L2 教程视频结构（与 Slides 共享骨架）

章节教程视频 = 对应 workshop deck 的"说话版"：
痛点引入(1min) → 五问工作流(2min) → Skill 选择演示(2min) → 实跑一个任务(4min) → 验收与常见坑(2min)。
**Slides 和视频共用同一份内容骨架，一次拆解两处产出。**

### 生产管线（半自动化）

```
章节 Markdown
   ↓ 脚本提取（结构化拆解：痛点/步骤/提示词 → 分镜脚本）
分镜脚本（每镜：画面来源 + 解说词 + 时长）
   ↓ 画面：案例截图平移缩放（Ken Burns）+ 补录屏
   ↓ 解说：TTS 初版（可用本机 audio_generation 能力）→ 人工复录精品集
   ↓ 合成：FFmpeg 批处理 / 剪映精修
成片 + 字幕 + 封面（复用 268 张素材图）
```

### 发布顺序建议
先发 **案例纪录片**（第 11 章办公三件套、年报案例——共鸣最强）验证数据，再决定教程系列的投入。短视频同步日更养号。

## 五、三形态协同：一份内容，三次变现

```
                    章节 Markdown（母本）
                   ↙        ↓        ↘
              Slides      视频      网站
           （教学骨架） （传播引流）（内容母港）
                   ↘        ↓        ↙
              视频简介 → 网站章节 ← Slides 结尾二维码
              网站内嵌视频与 deck 下载，形成闭环
```

**关键原则**：
1. **单一母本**：所有形态从 Markdown 章节生成，改内容只改母本，重新生成衍生形态
2. **Slides 与视频共享骨架**：章节拆解一次，两处复用
3. **网站是终点**：所有外部流量（视频平台、分享出去的 deck）最终导流回网站

## 六、执行路线图（Phase）

| Phase | 周期 | 动作 | 产出 | 验证标准 |
|-------|------|------|------|---------|
| **P0 基建** | 3 天 | 仓库依赖安装、`vitepress build` 验证通过；建立"章节 → 分镜/分页"拆解模板 | 可构建的站点 + 1 个示范拆解 | build 成功，模板覆盖一章 |
| **P1 网站上线** | 1 周 | 按 `DEPLOYMENT.md` 部署；配置 SEO（已有 `SEO.md` 清单） | 线上可访问的文档站 | 搜索引擎收录 |
| **P2 Slides 产线** | 2 周 | Slidev 模板开发（像素绿主题）→ 先做总览 deck + 第 11 章 workshop deck 两个样板 → 批量剩余章节 | 2 个样板 deck + 批量产线 | 样板对外分享收集反馈 |
| **P3 视频启动** | 3 周 | 第 11 章教程视频 + 年报案例纪录片 + 3 条短视频，跑通管线 | 5 条成片 | 播放/完播数据决定后续投入 |
| **P4 规模化** | 持续 | 按数据反馈批量：短视频周更、教程覆盖第一篇 10 章、deck 补齐 27 章 | 完整内容矩阵 | 网站流量与转化率 |

### 与本工作区已有资产的协同
- 转化方法论沿用 `docs/ai-edu/` 的内容基因（钩子先行、Before/After、可执行的下一步）
- 批量化阶段可接入 ContentForge 管线（采集 → 处理 → 发布）做多平台分发
- 拆解模板、分镜模板可固化为 Skill 复用

## 七、风险与注意点

1. **内容时效性**：蓝皮书基于特定 WorkBuddy 版本，视频/Slides 一旦录制定型，产品 UI 更新后维护成本高——短视频优先用"方法"视角（五问工作流、人机分工）而非纯 UI 跟点，降低过时速度
2. **268 张截图的版权与隐私**：案例截图需检查是否含用户真实数据，对外发布前过一遍脱敏
3. **不要三种形态同时铺开**：按 P0→P1→P2→P3 顺序，每个 Phase 有验证标准，数据不好就停在那个形态迭代，不进入下一阶段
